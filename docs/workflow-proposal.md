# 网页对话驱动的科研图重建工具包（讨论稿）

此文档是推荐路线，不是已完成工具，也不是已批准的全部实现要求。已确认约束见 [决策记录](decisions.md)。

## 建议交付形式

| 组成 | 作用 | 输入与输出 |
| --- | --- | --- |
| 通用对话手册与分轮提示词 | 在支持看图的网页模型中复用同一流程 | 原图与约束 → 元素清单、文字清单、连接关系与布局草案 |
| 统一图纸格式 | 让网页模型的输出可以交给确定性工具执行 | 分组结构、稳定元素 ID、坐标、样式、素材引用与待确认项 |
| Figma 导入与更新工具 | 建立原生文字和图形对象，导入矢量图标；按 ID 更新已有对象 | 图纸与素材 → 可编辑 Figma 图层 |
| 对照校正与检查工具 | 生成同尺寸对照图，检查结构和位图边界 | 原图与重建结果 → 校验报告、对照图与局部修改清单 |

通用提示词是基础；可选增加 Codex 技能封装。普通网页聊天不应被假定能够直接运行本地工具、检索网站或写入 Figma。具体模型的可用工具需在使用时确认。

## 建议使用顺序

1. 上传参考图，确认真实画布尺寸、分区、文字与连线关系。复杂图按分区处理。
2. 生成图标与图片素材清单，给每项分配稳定 ID。
3. 准备输入 RGB 和输出结果图；其余素材必须是矢量。
4. 网页模型按分区输出约定图纸，工具校验字段、坐标、引用与分组。
5. 导入 Figma，文字、模块、箭头分别建立可编辑对象；图标导入 SVG 或绑定已有矢量素材。
6. 导出同尺寸预览，回传给视觉模型与原图比较；通过局部修改更新图纸与 Figma，避免每次重建整张图。
7. 检查文字、连线、分组、允许的位图位置、字体、论文尺寸与导出质量。

第一版已确认接受在网页模型和工具之间人工上传、下载或复制文件，工具负责建图与校验。后续网页自动操作尚未决定。精度目标需用一个小样验证，不能仅凭模型看图承诺逐像素一致。

## 图标策略

- 优先复用同款 SVG、原始矢量资产或用户已有的 Figma 图标资源。
- 对有检索接口的图标库，可以由工具检索并取得 SVG，视觉模型帮助判断候选是否匹配。现有插件导入的图标也可以作为人工补充素材。
- 已确认还原优先：找不到同款时尝试忠实矢量重绘，难处理的单独标记。相似图标替换未获授权。
- 自动描摹可以作为复杂扁平图标的候选办法，但轮廓精度、路径数量和编辑质量需要单独评估。
- 保存图标来源、版本或资源 ID，以及相应许可信息，便于复用。

依据：[Iconify 检索接口](https://iconify.design/docs/api/search.html)、[SVG 获取方式](https://iconify.design/docs/api/svg.html)、[Figma SVG 导入能力](https://developers.figma.com/docs/plugins/api/figma/#createnodefromsvg)。这些文档证实了技术构件存在，不证明已经完成整图重建或图标自动匹配。

## 可借鉴的现成流程

Image To Slice 的 [手动 JSON 模式](https://github.com/50kg/image-to-slice/blob/main/docs/manual-json-mode.md)已经描述“网页模型分析 → JSON 与素材 → Figma 图层”的免 VLM API 操作路径。

其文档中支持的元素是 text、rectangle、image、group、container、frame，明确排除 ellipse、icon、svg、gradient 等输入类型。因此可以借鉴交接与校验机制；本项目需要的科研连线、矢量图标和视觉效果还需另行设计与验证。
