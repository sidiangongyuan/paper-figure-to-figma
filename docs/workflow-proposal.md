# 网页对话驱动的科研图重建工具包（讨论稿）

此文档是推荐路线，不是已完成工具，也不是已批准的全部实现要求。已确认约束见 [决策记录](decisions.md)。

已有场景执行原型，并完成了一个整图样例的 Figma MCP 建图与导出，见 [首次测试](pilot-01.md)。完整通用工具包、任意图片自动识图和不依赖 MCP 的本地插件仍未实现。

## 统一交付形式（当前建议）

回应用户希望统一 A/B 的诉求，建议交付一个科研图重建工具包，同时包含 Figma 插件、代理 Skill、通用网页指令包和示例。A/B 表示使用入口，不能作为互斥的产品选择。以下是目标结构，不代表这些组件已经封装完成。

| 组件 | 使用者与职责 |
| --- | --- |
| Figma 插件 | 用户在 Figma 中导入模型图纸和素材、查看错误、应用修改、导出画板与文件 |
| 代理 Skill | 在支持工具调用的代理中编排识图、图纸生成、素材处理、Figma 写入、预览复核和修订 |
| 通用网页指令包 | 网页用户直接复制分析、重建、复核指令；与 Skill 使用相同的图纸规范和默认样式 |
| 共用执行核心与示例 | 共享图纸解析、校验、矢量绘制、关键特征与排版检查；各入口不另写一套还原规则 |

### 两种入口，共用工程

- 网页入口：参考图 → 网页模型 → 图纸与素材 → 用户导入 Figma 插件 → 预览与局部对照 → 网页模型输出修订 → 插件更新。
- 代理入口：参考图 → Skill 编排看图和图纸生成 → 共用校验与绘制核心 → 已连接的 Figma 写入工具 → 预览与修订。

网页用户只需使用插件与通用指令包，不要求安装 Skill 或配置 MCP。代理入口需要 Skill 以及实际支持 Figma 写入的工具连接；Skill 本身不增加写入权限。代理可通过 MCP 执行绘制，不需要假定它能自动打开或操控插件界面。

统一的是图纸、素材、样式、稳定元素 ID、修订约定和验收规则。网页模型的会员不会因为安装 Skill 就自动变成 API，也不默认自动接管任意网页聊天。第一版保留已接受的人工交接，不以网页自动化或 VLM API 为前提。

同一工程的目标是能够从网页入口转交代理继续修改，也能由插件打开代理生成的工程。跨入口切换和通用增量更新尚未验证，不能把当前单样例的定制修正当作成品能力。

### 交付与实现边界

最终交付包应同时提供可安装的插件、可安装的 Skill、网页指令包、教程与合成示例；用户按自己的入口安装所需组件。每张图的交付仍为可编辑 Figma 画板、SVG/PDF、工程图纸与素材、差异和疑点清单。

现有绘制脚本包含 MCP 运行时专有的状态辅助能力，尚不是可以直接发布的普通 Figma 插件。下一步需提取环境无关的图纸与绘制核心，将素材上传、目标文件定位、状态显示和导出取回等差异放入插件/MCP 适配层，再封装两个入口。优先复用已经测试的绘制规则，避免两端在字体、渐变、底板和曲线处理上产生分歧。

验收需覆盖：同一工程在两端绘制结果一致；重复导入不产生重复对象；修改通过稳定 ID 定位；渐变、底板、曲线、字号和位图边界在两端遵守相同规则。当前仍处于场景执行原型阶段。

## 共用流程组成

| 组成 | 作用 | 输入与输出 |
| --- | --- | --- |
| 通用对话手册与分轮提示词 | 在支持看图的网页模型中复用同一流程 | 原图、约束与可选辅助材料 → 元素清单、文字清单、连接关系与布局草案 |
| 统一图纸格式 | 让网页模型的输出可以交给确定性工具执行 | 分组结构、稳定元素 ID、坐标、样式、素材引用与待确认项 |
| Figma 导入与更新工具 | 建立原生文字和图形对象，导入矢量图标；按 ID 更新已有对象 | 图纸与素材 → 可编辑 Figma 图层 |
| 对照校正与检查工具 | 生成同尺寸对照图，检查结构和位图边界 | 原图与重建结果 → 校验报告、对照图与局部修改清单 |

通用指令与 Skill 应复用同一份规范。普通网页聊天不应被假定能够直接运行本地工具、检索网站或写入 Figma。具体模型的可用工具需在使用时确认。

## 已确认的标准输入

图片是唯一必需的源材料；可以是 AI 生图，也可以是已有科研图。原始生图提示词、图注、文字或公式清单是可选辅助材料。图片作为还原依据，不清楚的内容及与辅助材料的冲突列入疑点清单，修正经用户确认后执行。

直接输入完整参考图，无需用户自行裁剪或选择 (d) 区域。规划中的流程先理解全局布局与跨区连线，再内部分区重建，最终以完整可编辑的 Figma 画板为交付目标。

原始生图提示词与用于指导视觉模型重建的指令不同。用户无需知道原作者如何制作图片；工具包提供分轮重建指令，用户将参考图与对应指令交给网页模型即可开始。

## 已确认的编辑标准

正文默认 Times New Roman，标题可用 Times New Roman 或 Comic；编辑画布默认字号至少 16，允许调整画布。用户已确认这不代表论文最终缩放后的字号也为 16；最终版面需要单独验收。用户明确指定字体时覆盖默认值。

- 文字保持可编辑文本，能够直接修改内容、字体和字号。
- 模块框能够独立调整位置、尺寸、颜色和圆角。
- 箭头能够独立调整路径、端点、粗细和虚实。
- 图标按整体分组，内部保留可编辑的矢量路径。

这些标准定义交付后的编辑能力，不等于已确定导入格式与实现细节，也不自动包含模块移动时连线跟随等能力。

## 已确认的原图疑点处理

重建先忠实还原参考图；发现错字、文字挤压、明显错位或连线疑点时，单独列出问题及其位置。修正经用户确认后执行，包括涉及方法含义的修改。还原结果与问题清单保留明确对应关系，便于对照验收。

## 内部分步验证

此前选择先验证包含文字、几个模块、箭头和一个复杂图标的代表性局部。这属于内部开发步骤：从完整参考图中选取测试区域，不要求用户裁图，也不限制最终交付范围。此前建议的 (d) 区域不是固定要求。现已完成第一张完整四分区图的测试和用户复核后的修订；其余两张仍需验证。

建议验证产物为局部元素与连接清单、Figma 可编辑图层、同尺寸对照预览，以及疑点和偏差清单。检查文字是否可改、模块与箭头是否独立、图标是否为矢量，并对照布局与连接关系。局部结果用于评估可行性；整图布局、复杂连线与最终精度标准需后续验证。

## 建议使用顺序

1. 上传完整参考图，可附原始生图提示词或图注等辅助材料；先确认整图尺寸、全局布局、分区、文字与跨区连线关系。内部分区放大，单独列出渐变、浅色底板、透明度、遮挡顺序与曲率；先对照原图检查这份清单是否完整。
2. 生成图标与图片素材清单，给每项分配稳定 ID。
3. 准备输入 RGB 和输出结果图；其余素材必须是矢量。
4. 网页模型在统一画布坐标与样式约定下按分区输出图纸，保留跨区连接关系；关键视觉特征绑定元素 ID，工具校验字段、坐标、引用、分组、已列出的视觉特征与编辑字号。
5. 在完整 Figma 画板中合并各分区，文字、模块、箭头分别建立可编辑对象；图标导入 SVG 或绑定已有矢量素材。
6. 导出同尺寸整图与局部预览，回传给视觉模型与原图比较；先列差异再查图层，检查整体对齐、跨区连线及渐变、底板、曲线等细节。通过局部修改更新图纸与 Figma，避免每次重建整张图。结构计数不能替代视觉验收。
7. 检查文字、连线、分组、允许的位图位置、字体、论文尺寸与导出质量。

第一版已确认接受在网页模型和工具之间人工上传、下载或复制文件，工具负责建图与校验。后续网页自动操作尚未决定。精度目标需用一个小样验证，不能仅凭模型看图承诺逐像素一致。

## 图标策略

- 优先复用同款 SVG、原始矢量资产或用户已有的 Figma 图标资源。
- 对有检索接口的图标库，可以由工具检索并取得 SVG，视觉模型帮助判断候选是否匹配。现有插件导入的图标也可以作为人工补充素材。
- 已确认还原优先：找不到同款时尝试忠实矢量重绘，难处理的单独标记。相似图标替换未获授权。
- 自动描摹可以作为复杂扁平图标的候选办法，但轮廓精度、路径数量和编辑质量需要单独评估。
- 保存图标来源、版本或资源 ID，以及相应许可信息，便于复用。

依据：[Iconify 检索接口](https://iconify.design/docs/api/search.html)、[SVG 获取方式](https://iconify.design/docs/api/svg.html)、[Figma SVG 导入能力](https://developers.figma.com/docs/plugins/api/figma/#createnodefromsvg)。这些文档证实了技术构件存在，不证明已经完成整图重建或图标自动匹配。

## 可借鉴的现成流程

Image To Slice 的 [手动 JSON 模式](https://github.com/50kg/image-to-slice/blob/main/docs/manual-json-mode.md)已经描述“网页模型分析 → JSON 与素材 → Figma 图层”的免 VLM API 操作路径。

其文档中支持的元素是 text、rectangle、image、group、container、frame，明确排除 ellipse、icon、svg、gradient 等输入类型。因此可以借鉴交接与校验机制；本项目需要的科研连线、矢量图标和视觉效果还需另行设计与验证。
