## 当前步骤

第一问已通过三张参考图明确图类型。参考图并不自动代表第一版必须支持其中每一种视觉细节。

第二问已确认：位图例外仅限输入 RGB 和输出结果图。其他区域不得通过嵌入图片绕过矢量重建要求。

第三问讨论 Figma 内的编辑粒度。用户补充图标是难点：平常通过 Figma 图标插件导入，需要设计合适的 AI 辅助方案。此回答尚未确认文字与其他元素的全部编辑粒度。

用户随后明确网页模型会员与无 VLM API 的约束，因此先讨论工具包形式与网页到 Figma 的交接方式，再回到图标策略和编辑粒度。

当前建议为通用分轮提示词、结构化图纸、Figma 导入器与对照校正流程。人工复制/上传、Codex 技能封装、网页自动操作均尚未决定。

## 后续决策依赖

以下为讨论顺序草案，不是已确认需求，也不是同时要求用户回答的问题。

1. 代表性参考图与第一版覆盖范围。
2. 编辑能力：文字、模块、箭头、图标分别需要怎样编辑；是否要求 Figma 原生节点。
3. “1:1”如何验收：布局、文字、颜色、形状、局部细节分别允许多少偏差。
4. 在已确认的位图边界下，复杂图标、插画、纹理等如何做矢量重建。
5. 原图中科学表达或文字有错误时，如何由用户确认修正。
6. 输入材料：单张图片，或同时提供提示词、文字清单、原始数据等。
7. 自动化程度与人工校正步骤。
8. 模型/API、Figma 接入方式、运行环境与预算。
9. 输出格式、字体、论文尺寸与质量检查。
10. 小样验证后再确定实施路线和第一版范围。

## 约束

- 外观相似、真正矢量化、便于编辑、科学表达正确，需要分别检查。
- SVG 文件后缀不能单独证明内容全部是矢量；也不能证明文字仍可作为文字编辑。
- 当前没有承诺任意图片都可自动、无损、全矢量重建。
- 每项决策标明来源；推荐方案在用户确认前保留为候选。
